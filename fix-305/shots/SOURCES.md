## Notes on the captures

- Every capture under `../evidence/` starts with the provenance header its script wrote on S3DF (host, date, commit, cmd). The run logs were written by `evidence/harness/run_thr.sh` (scripts' sha256 prefixes in each log's line 5 match the copies in `evidence/harness/`); the diff by `diffcap.sh`; the timing table by `timingsum.sh` from the nine runs of `timing2.sh`.
- The `[PSANA-INFO ...] unable to connect to https://pswww.slac.stanford.edu/...` line in each run log is psana printing its hard-coded logbook URL. The request itself went to the loopback stand-in (`shim/sitecustomize.py` rewrites it; the stand-in counted "logbook requests 1"), which answers 404, so psana uses the files on disk. Each run was inside a private network namespace whose only link is `lo` (line 8 of each log).
- The recording is the team's shared simulated Jungfrau run (one 512 x 1024 module, 2080 events, lcls2 sim-main 145dd2b, `daqrun.sh record`). Its unmasked pixels all reach a calib of 5 or more at some event, which is why `calib_max` is right at master with MFX's order on this recording; the saved full images and the mixed order show the bug instead.
- Nothing was edited in any capture; images show line ranges of the files, with elision rows where lines are left out.
